## デモの台本（3分・SPEC §13）

1. **ユーザーA（スマホ）**: 匿名ではじめる → チェックイン（エネルギー3）→ AIに「サークルで浮いていて、誰にも話せない」と相談
2. AIが傾聴したあと、つながりを提案 → 要約を確認し、少し編集して「共有する」
3. 候補に **ユーザーB（チームメンバーのPC）** が出る → リクエスト
4. Bが承諾 → ルームが始まり、AI司会が自己紹介を促す
5. AがLINEのIDを送ろうとする → **自動でマスク**され、司会が匿名のまま話すよう促す
6. 否定的な発言が続く → 司会が視点を変える質問をする
7. **ユーザーC（別のブラウザ）**: AI相談で危機を表す表現 → **即座に危機対応画面**。候補一覧に進めないことを見せる
8. Aが1タップで退出 → 振り返り（気分の再チェック）
9. ロードマップ

### デモ前の準備

- [ ] 3つのブラウザ（A・B・C）を用意し、それぞれ別のユーザーでサインインしておく
- [ ] デモ用のシードユーザーに `is_demo=true` が付いている（AIが人間のふりをしない）
- [ ] 画面のタイマーを短くする設定（`NEXT_PUBLIC_DEMO_FAST_TIMER=true`）を確認
- [ ] 通信が切れたときのために、**予備のデモ動画**を撮っておく
- [ ] 危機対応のデモ文は、実在の相談内容ではなく、ダミーの文を使う

## 想定される質問と答え（たたき台）

| 質問 | 答え |
| :-- | :-- |
| 危機の人が使ったらどうなる？ | 危機を検知したら、人とのマッチングを止め、専門の相談窓口を最優先で表示する。AIは診断や治療の助言をしない |
| 悪意のある人が来たら？ | 完全匿名、ブロック・通報は1タップ、通報があればルームを自動で終了する。個人情報は自動でマスクする |
| 悩みの深い人同士がつながると共倒れにならない？ | エネルギーが低い人同士はマッチさせない。30分の上限と、AI司会の介入で視点を変える |
| 専門家の監修は？ | 今回は公開指針から安全チェックリストを作った。将来は、精神科医・公認心理師による監修体制を作る |
| ユーザーがいないとき（コールドスタート）は？ | リクエストを残しておく方式にしている。デモ用のシードユーザーには、デモ用だと分かる印を付けている |
| 相談内容はどこに保存される？ | AIとの会話はブラウザだけで、DBには保存しない。保存するのは、本人が承認した要約だけ（24時間で期限切れ） |
