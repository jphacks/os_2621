専門家の監修の代わりに、公開されている指針をもとに自分たちで作ったチェックリストです（SPEC.md §11）。
デモの前に、全項目を確認して、確認した日と人を書き込みます。

- 確認日: ____

## 動作確認の記録

実際のSupabase + Gemini（無料枠）で、`claude/integration` を動かして確認した内容です。
**チェック欄（済）は、項目の確認方法どおりに確かめられたものだけに付けます。** 下の「通ったこと」は、流れとして動いたことの記録です。

### 2026-10-17（Cさんが確認）

通ったこと:
- P0 → P1（匿名ではじめる）→ P2（チェックイン）→ P3（AIの返事がストリーミングで出る）
- P4（要約の作成・編集・共有）
- 危機を表す文を送ると、サーバーが検知して記録する（ログ `[chat] L1 crisis`）。そのユーザーは、以後「今は少し時間をおきましょう」と出て、「話を整理する」が押せない（A5・A6の一部）
- L2（危機判定）が失敗したとき、マッチングが止まる（Geminiのモデル名が合わず404になったときに確認。A4に近い状況）
- P5（候補が出る）→ リクエスト送信 → 別ユーザーが承諾 → 両者がルームに入る

まだ確認していないこと（確認方法は、各項目の表のとおり）:
- ルームでのLINEのID等のマスク（C2・C3）
- 退出・ブロック・通報が、相手の画面にすぐ反映されるか（D2）
- ルームで危機を表す発言をしても、相手に届かないか（A7）
- 全データ削除のあと、要約が候補に出ないか（B6）
- 司会（AI）の介入、3分（デモ設定）での終了
- 診断名の断定・薬や治療の助言をしないか（D5）
- 窓口の電話番号と受付時間の、公式サイトでの確認（A8）
